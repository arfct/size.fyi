# Contributing to size.fyi

The easiest way to help is to **add a device**. It's a single JSON file and a pull request — no build tooling knowledge required.

## Add a device

1. Copy [`data/devices/device.template.json`](data/devices/device.template.json) to `data/devices/<category>/<slug>.json`.
   - The folder **must** match the device's `category` (e.g. a phone goes in `data/devices/phone/`).
   - The filename should be the `slug` (e.g. `iphone-17-pro.json`).
2. Fill in the fields (see the schema below). Dimensions are in **millimetres**.
3. Run `npm run validate`. Fix anything it reports.
4. Open a pull request. CI re-runs validation automatically.

One device per file keeps pull requests small, reviewable, and conflict-free — two people adding two devices never touch the same file. The compiled catalog (`public/devices.json`) is generated by the build and is **not** committed; you never edit it by hand.

## Schema

```jsonc
{
  "slug": "iphone-17-pro",        // required: kebab-case, [a-z0-9-]; must be unique; no "-vs-" or "~"
  "name": "iPhone 17 Pro",        // required: display name
  "category": "phone",            // required: everyday | paper | phone | tablet | laptop | console | pc-case | audio | camera | watch
  "h": 150, "w": 72, "d": 8,      // required: height × width × depth in mm (0.1–100000)

  "make": "Apple",                // optional: manufacturer
  "model": "A3001",               // optional: model number
  "year": 2026,                   // optional: release year
  "rank": 50,                     // optional: sort weight (higher = more prominent in search)
  "source": "https://…",          // optional: where the dimensions came from (encouraged)
  "url": "https://…",             // optional: product page (must be https://)
  "aliases": ["iphone 17 pro"],   // optional: extra search terms

  "radius": 12,                   // optional: corner/edge fillet radius in mm
  "radiusAxis": "z",              // optional: axis the rounded edges run parallel to — x | y | z.
                                  //   Omit radiusAxis to round ALL edges (like an AirPods case).
  "screen": { "h": 145, "w": 68, "radius": 12 }  // optional: front screen cutout (must fit within h/w)
}
```

### Rounding

- `radius` **with** `radiusAxis` rounds the four edges parallel to that axis — `x` (width), `y` (height), `z` (depth). Use this for phones, tablets, cans (a can is `radiusAxis: "y"` with `radius` = half the width).
- `radius` **without** `radiusAxis` rounds *every* edge (a rounded box). Use for things like earbud cases.
- `radius` must be ≤ half the smaller of the two dimensions in its cross-section.

### Multi-state devices (foldables)

Devices that change shape (a folding phone open vs. closed) use `states` instead of top-level geometry. Put `h`/`w`/`d`/`radius`/`radiusAxis`/`screen` on each state, **not** on the device:

```jsonc
{
  "slug": "galaxy-z-fold8",
  "name": "Galaxy Z Fold8",
  "category": "phone",
  "defaultState": "closed",       // which state to show first (defaults to the first entry)
  "states": [                     // 2+ states, each with a lowercase-alphanumeric label
    { "label": "closed", "h": 153, "w": 68, "d": 12, "radius": 11, "radiusAxis": "z", "seam": true },
    { "label": "open",   "h": 153, "w": 132, "d": 6, "radius": 11, "radiusAxis": "z" }
  ]
}
```

- `seam: true` draws the fold parting-line on the 3D model for that state.
- A state is addressable in the URL as `slug-label`, e.g. `/galaxy-z-fold8-open`.

### 3D models and special meshes

- `model3d`: `{ "url": "name.glb", "rotation": [x, y, z] }` — the `.glb` must exist in `public/models/`. Mutually exclusive with `mesh`.
- `mesh`: a named built-in mesh (currently only `"banana"`). Mesh devices define their own geometry — don't set `radius`/`screen`.

## Running things

```sh
npm install
npm run validate   # check the catalog (what CI runs on your PR)
npm run dev        # run the app locally with your changes
npm test           # app + shared tests
```

The validator prints one line per problem, prefixed with the file and slug, so a failing PR check tells you exactly what to fix.
